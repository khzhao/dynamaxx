# Incremental Tropical WTG Mass-DSE Growth Filter

## Hypothesis

The accepted WTG filter improved the incumbent, but it relaxes the absolute
low-mode tropical mass-DSE anomaly after every positive-time step. The two most
recent rejected variants show that simply narrowing the mask or changing the
post-clipping neutrality is not enough. A different failure mode is that part
of the absolute tropical anomaly is useful analyzed or seasonal structure, while
the harmful component is the anomaly growth newly generated by the dry sigma
core during each inner step.

Filtering only the per-step growth of the WTG mass-DSE anomaly should preserve
the accepted tropical/free-tropospheric balance mechanism while reducing
over-flattening of real tropical wave and Hadley/Walker thermal structure.

## Mechanism

Add one side-by-side model, for example `dino_hsl2_mass_dse_wtg_incremental`,
derived from `dino_hsl2_mass_dse_wtg`. Keep the accepted latitude envelope,
sigma envelope, low-mode projection, relaxation timescale, temperature cap,
positive-time-only placement, finite fallback, and output contract.

Replace the absolute-anomaly WTG correction with a growth-form correction:

- diagnose the accepted low-mode mass-DSE anomaly for both `prev_state` and
  raw `next_state`;
- form the per-step growth `low_mode_mass_dse_next - low_mode_mass_dse_prev`;
- remove the tropical layer mean of that growth under the accepted WTG weights;
- apply the accepted WTG relaxation fraction to only the masked growth term;
- convert the bounded mass-DSE correction to a temperature increment using
  guarded layer pressure thickness and `Cp`;
- preserve the accepted layer-neutral temperature offset and finite fallback.

The candidate does not touch vorticity, divergence, log surface pressure,
tracers, HSL departure geometry, weak-HS forcing, surface fluxes, output
packing, or fixed evaluation protocols.

## Implementation Scope

- Expected files: add one opt-in growth-form WTG selector in `adapter.py`,
  expose one factory through `__init__.py`, register one model key, and add
  focused tests.
- Registry changes: add `dino_hsl2_mass_dse_wtg_incremental`; keep
  `dino_hsl2_mass_dse_wtg` exactly unchanged when the selector is disabled.
- API changes: none to `ForecastInput`, `WeatherState`, target variables, lead
  times, or metric protocols.
- Tests to update: registry construction; disabled-path incumbent equivalence;
  exact no-op when the WTG anomaly is unchanged between `prev_state` and
  `next_state`; finite fallback on invalid pressure thickness or DSE
  diagnostics; cap and layer-neutrality checks on synthetic growth fields.

## Expected Metric Movement

- Expected improvements: `mean_sea_level_pressure`, `geopotential_500`, and
  `10m_u_component_of_wind` at medium leads if the accepted WTG gain comes from
  suppressing model-generated tropical thermal imbalance rather than damping
  the inherited anomaly itself.
- Expected neutral metrics: `2m_temperature` should remain close outside the
  tropical WTG mask because surface residuals and lower-boundary forcings are
  unchanged.
- Possible regressions: if the accepted benefit depends on continuously
  relaxing the full absolute anomaly, a growth-only filter can be too weak and
  lose the incumbent's validated gain.

## Risks

- Numerical stability: low to moderate; the operation is still a capped
  thermodynamic filter but now depends on both previous and next diagnostics.
- Compute cost: low to moderate; it roughly doubles the WTG diagnostic work for
  the filter because both states are inspected.
- Data leakage: none; it uses only current rollout states and fixed masks.
- Physical plausibility: moderate; WTG balance supports weak tropical
  temperature gradients, and filtering generated imbalance is less intrusive
  than repeatedly relaxing the full analyzed anomaly.
- Rollback complexity: low; one selector, one factory/export, one registry
  entry, and focused tests.

## Evaluation Plan

- Fast gate: run `uv run pytest` and `uv run dynamaxx-eval fast --model dino_hsl2_mass_dse_wtg_incremental`; require finite output and zero diagnostics issues.
- Iteration gate: run the fixed iteration protocol and compare against the
  compatible cached `dino_hsl2_mass_dse_wtg` incumbent metrics from
  `.logbook/leaderboard.json`; do not rerun the incumbent unless the cache is
  concretely invalid under `roles/PROTOCOL.md`.
- Validation gate: run fixed validation only after iteration promotion.
- Outcome that would falsify the hypothesis: a clean subthreshold or negative
  iteration delta would show the accepted WTG improvement relies on absolute
  anomaly relaxation, not just damping model-generated growth.

## Researcher Notes

This is not another WTG spatial-support narrowing or post-clipping conservation
closure. It keeps the accepted WTG support and invariant but changes the
quantity being relaxed from the absolute anomaly to the step-generated anomaly
growth. It is also distinct from staged first-baroclinic, zonal-anomaly, and
time-centered WTG ideas, which change vertical structure, zonal decomposition,
or operator placement rather than the absolute-vs-growth target.

## Evaluator Notes

### 2026-06-25T12:26:00Z

Decision: move to `staging`; ranked 2 of 3 new proposals.

This is a valid bounded side-by-side WTG idea. It keeps the accepted WTG mask,
vertical envelope, low-mode projection, cap, positive-time placement, output
contract, and fixed evaluation protocols unchanged. It is also not a duplicate
of the two latest rejected WTG follow-ups: it changes the relaxed quantity from
absolute anomaly to per-step generated growth rather than narrowing support or
adjusting only the neutralization closure.

The reason to stage rather than ready it is expected signal and cost. The last
two WTG variants were safe and guardrail-clean but lost primary score, which is
evidence that small weakening or reshaping of the accepted WTG operator is not
enough to clear the `+0.002` iteration threshold. This proposal may preserve
more analyzed tropical structure, but it can also remove the incumbent's useful
absolute-anomaly relaxation and become too weak. It also roughly doubles the
WTG diagnostic path because both previous and next states must be diagnosed,
which matters after recent slow iteration runs.

Keep staged as the best lower-risk WTG follow-up if the high-signal vertical-DSE
ramp is rejected or proves too hard to implement cleanly. It should not take the
next ready slot ahead of the guarded vertical-DSE test.
